Three-tier adoption shape

Adoption is not all-staff. Different roles need different tooling. The leverage compounds when Tier 2 builds skills that Tier 3 reuses — confirmed by Ruben Hassid's 290k-subs counter-data-point above.

Engineering / AI team

Senior power users — 1–2 leads per discipline
Claude Code CLI + IDE · Cost: Team plan + meaningful API

Tier 3 · ~100+ people
Production marketers — ad ops, junior SEOs, content writers, AMs
Claude.ai Team plan + Claude Cowork · Cost: per-seat
Consume the skills Tier 2 builds via Cowork (Ruben's pattern). Don't write new skills; run existing ones, request fixes when outputs miss. Terminal/CLI is a graduation path, not a default.

CRAAP-derived · 7 dimensions · max 35 · stricter v3 thresholds

The framework follows the standard CRAAP test (Currency, Relevance, Authority, Accuracy, Purpose) used in academic information literacy[13], extended with ADOPT (external validation / market traction) — a domain-specific addition for the open-source ecosystem where adoption velocity matters.

7 scoring dimensions (1–5 each)
AUTH · Authority — credibility of the source itself. AgriciDaniel (handle) = 2. Anthropic primary = 5.
SPEC · Specificity — exact metrics with methodology vs. vague enthusiasm.
INDP · Independence — commercial interest in promoting Claude Code (vendor = 1, observer = 4).
RCNT · Recency — 2026 = 5, ≤ 2024 = 1.
VRFY · Verifiability — open-source/dataset = 5, anecdotal = 1.
MTCH · SEONGON service match — direct = 5, unrelated = 1.
ADOPT · Adoption — 3,000+ stars / canonical = 5, < 50 = 2 (the GitHub-handle vs market-acceptance split).
Framework lineage: CRAAP (library science) + ADOPT (OSS-era extension). Adjacent: GRADE (medical evidence), Cochrane risk-of-bias tool, ACRL Information Literacy Framework. No published market-research source-grading framework — this is custom but standards-rooted.

Open questions for SEONGON-internal phase

These need internal data, not desk research. They gate the move from research pack to formal proposal.

  1. Q1 · Baseline
    Current per-account fulfillment hours by service line

    Without this, the time-savings projection is industry-average, not SEONGON-specific.

  2. Q2 · Stack
    Client mix by martech stack (HubSpot vs. Salesforce vs. nothing)

    Drives the integration build order for marketing-ops automation.

  3. Q3 · Content
    Vietnamese AI-content detector landscape

    Drives anti-slop layer design. Need to know which detectors clients use and at what thresholds.

  4. Q4 · Demand
    Existing-client appetite for GEO consulting upsell

    Drives whether GEO becomes a productized service in 90 days vs. 12 months.

  5. Q5 · Capacity
    Senior time available for skill-building vs. running current accounts

    Drives realistic pilot timeline. Tier 2 work is meaningful upfront investment.

  6. Q6 · Cowork policy
    Privacy + compliance posture for Cowork desktop sandbox

    Tier 3 (100+ marketers) consumes via Cowork. Need IT/legal policy on what data can flow through it before mass onboarding.
