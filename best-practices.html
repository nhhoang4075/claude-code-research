01 · Hiệu suất

Lấy output chất lượng cao nhất — không phải code nhanh hơn, mà suy nghĩ đúng hơn

Output Claude Code tốt hay tệ phụ thuộc 80% vào pattern bạn dùng — không phải model. Default Sonnet 4.6 cho 80% việc, escalate Opus 4.7 khi cần lý luận sâu, Haiku 4.5 cho task cơ học.

Pricing 3 model — per 1M tokens
Tỷ lệ: Sonnet ≈ 3× Haiku · Opus ≈ 5× Haiku · 2026-Q1 pricing
Haiku — input Haiku — output Sonnet — input Sonnet — output Opus — input Opus — output

Caveat tokenizer Opus 4.7: Pricing per token không đổi nhưng tokenizer mới có thể generate ~30-35% nhiều token hơn cho cùng input. Cost thực có thể cao hơn pricing list 30-40%. Sonnet 4.6 vẫn là daily driver tốt nhất về ROI cho marketing task lặp lại.

11 pattern hiệu suất

1
Chọn model đúng
Default Sonnet 4.6. Escalate Opus 4.7 cho lý luận sâu, dữ liệu lớn. Drop Haiku 4.5 cho batch task.
SEONGONSEO senior chiến lược cluster 50 keyword → Opus. Junior viết 10 meta-desc → Sonnet. Bulk rephrase 200 RSA → Haiku.
2
Plan mode trước task lớn
Shift+Tab vào plan mode. Claude khảo sát read-only, đề xuất plan, bạn duyệt rồi mới execute. 2K plan cứu 50K sai hướng.
SEONGONMọi việc chạm client account thật (Ads, GSC, GA4, WordPress prod) — bắt buộc plan mode trước.
3
Delegate cho subagent
Subagent có context riêng, chỉ trả summary. Dùng để khảo sát / research / review — không làm bẩn main session.
SEONGON5 subagent song song research 5 đối thủ. Code-reviewer subagent audit security trước deploy.
4
Gọi tool song song
Tool độc lập → batch trong 1 message. Mỗi vòng serial mất 2-5s latency. Dùng cho Read, Grep, Bash, MCP.
SEONGON"Fetch đồng thời GSC + GA4 + Ahrefs cho domain X" thay vì 3 round trip serial.
5
TDD / verification loop
Cho Claude cách kiểm chứng — test case, expected output, schema validator. Output tốt hơn rõ rệt.
SEONGONRSA headline ≤ 30 char — cho Claude regex check, fail thì tự rút ngắn.
6
Skill & slash command
Cùng prompt chạy ≥3 lần → biến thành skill. Lazy-load, không phá context. Hệ sinh thái sẵn có (claude-seo, claude-ads).
SEONGON/audit-seo, /brief-content, /qa-rsa — share qua git repo nội bộ.
7
CLAUDE.md hierarchy
User-level / project-level / subdir-level. Mỗi file < 30 dòng effective. Auto-memory persists qua session.
SEONGONĐã có ~/Work/CLAUDE.md — Bun, multi-project. Project-level cho từng repo riêng.
8
IDE diff review
VS Code / JetBrains diff preview. Junior dùng "Ask before edits". Senior quen code base có thể "Edit auto" cho task quen.
SEONGONMarketer dùng Cowork: "review" = đọc plan + output trước khi click Apply.
9
Hooks deterministic
PreToolUse, PostToolUse, UserPromptSubmit. Khác CLAUDE.md (advisory), hook chạy 100% theo config.
SEONGONHook chặn Write vào migrations/, log mọi Bash, IT setup chuẩn deploy qua dotfiles.
10
MCP server thay Bash
MCP có cấu trúc, ít token 30-70% so với curl/shell. GitHub, Drive, GSC, GA4, DataForSEO, Ahrefs đều có MCP.
SEONGONGSC MCP cho keyword performance. Custom MCP wrap dashboard nội bộ.
11
2025-2026 updates
Opus 4.7 step-change agentic + tokenizer +35%. Adaptive thinking. Cache TTL drop 1h→5min. April postmortem fix v2.1.116.
SEONGONTheo dõi Anthropic status page — regression đột ngột check trước khi đổ lỗi prompt.

02 · Chi phí

Scale agency mà không bùng cost — mục tiêu $50-150/người/tháng cho power user

Nếu mỗi người để Claude chạy Opus mặc định + idle session quá 5 phút thì agency margin sẽ chết. 11 pattern dưới giúp giảm cost 60-75% mà chất lượng không giảm rõ rệt.

⚠ Cảnh báo lớn nhất 2026

Cache TTL silently drop từ 1h xuống 5 phút (2026-03). Workflow nào dựa vào cache 1h hiện tăng cost 20-32%. Idle session > 5 phút = cache chết = lần dùng sau coi như session mới. Verify lại trên platform.claude.com/docs/en/build-with-claude/prompt-caching trước khi quyết định plan đắt.

Quy tắc 80/10/10 — model mix lý tưởng

Cache warm vs cold — 100K tokens
Sonnet 4.6 · re-read trong vs sau 5 phút TTL

11 pattern chi phí

1
Cache 5-min TTL
Cache write 1.25× input. Read 0.1× input. Break-even: ≥3 read trong 5 phút. Quá 5 phút idle → cache chết.
SEONGONTránh idle > 5 phút giữa session. Team 10 người dùng cache đúng cách ~$200/tháng tiết kiệm.
2
80/10/10 model mix
Sonnet $3/$15. Opus $5/$25. Haiku $1/$5. Tỷ lệ Sonnet 3× Haiku, Opus 5×. Mặc định Sonnet.
SEONGONJunior bị ép Sonnet qua CLAUDE.md. Senior strategy được phép Opus, review monthly cost.
3
/compact vs /clear
Còn cache (idle <5p) + cần giữ context → /compact. Cache chết (>5p) → /clear thường rẻ hơn /compact cold.
SEONGONTrước break: /compact nếu còn cache. Trước task không liên quan: luôn /clear.
4
Subagent isolation
Subagent context riêng. Trả về summary. Cha không gánh transcript. Tiết kiệm 90% main context cho research task.
SEONGONResearch 50K token → subagent → cha chỉ tốn 5K cho summary. Tiết kiệm 90%.
5
Plan-first ROI
Plan 2K token vs sai hướng 50K token. ROI 10-30× cho task phức tạp. Skip cho task < 1h hoặc 1 file.
SEONGONAudit SEO budget 30K. Vượt 50K → cái gì sai. Dừng plan lại, không cố một chút nữa.
6
Subscription plans
Pro $20/m. Max $100/m (5×). Max $200/m (20×). API pay-per-use. Break-even: 50M+ token/m → Max thắng.
SEONGONJunior: Pro. Senior heavy: Max $100. Strategy + Opus: Max $200. Pipeline 24/7: API + cap.
7
Token budget per task
Nhỏ <10K. Vừa 20-50K. Lớn 50-200K. Vượt 1.5× budget → abort, không "cố một chút". /cost xem usage.
SEONGONHook PostToolUse log token cumulative → tuần kiểm tra ai burn nhiều bất thường.
8
Read offset/limit + Edit
Đọc 50 dòng = 50 token, không phải 5000. Edit gửi diff, Write gửi cả file. Tiết kiệm 30-50% session cost.
SEONGON"Đọc auth section dòng 50-100" thay vì cả file. Edit content brief từng đoạn, không Write lại.
9
Background agent
Parallelization × N agent = × N cost (không chia). Tiết kiệm thời gian, không tiết kiệm tiền. Limit 4-8 worktree.
SEONGONResearch 10 đối thủ trước deadline khách → đáng. Chia nhỏ 1 task → vô nghĩa.
10
Tránh waste vặt
Đừng đọc lại file đã đọc. Đừng search redundant. Đừng Write lại sửa 5 dòng. Đừng để session idle.
SEONGONOnboarding 1h dạy 5 quy tắc → tiết kiệm $20-50/người/tháng. Train 1 lần, lợi mãi.
11
Pricing changes 2026
Cache TTL drop. Opus 4.7 tokenizer +35%. Workspace cache isolation. Đáng quan tâm nhất là TTL silent change.
SEONGONDefault Sonnet 4.6 cho đến khi Opus 4.7 tokenizer ổn định. Track actual token, không pricing list.

03 · Phát triển cá nhân

Tư duy & kiến thức — đừng để Claude làm thui chột nghề

Đặc biệt quan trọng cho non-developer ở SEONGON: SEO, paid media, content, analyst, AM. Cùng lý luận áp dụng cho dev junior. Mục tiêu: Claude khuếch đại năng lực, không thay thế nó.

01 · The big shift
Doing → Directing
Ngừng gõ, bắt đầu chỉ huy. Daily practice mới: 30% viết spec/brief + 50% review output + 20% intervene. Force multiplier chỉ kick-in khi bạn ngừng cố làm typist.
02 · Core skill
Đọc code/output thành kỹ năng cốt lõi
Không gõ thì phải đọc giỏi. Đọc mọi SQL, regex, JSON, n8n config Claude tạo. Test "narrate-back": kể lại được từng block làm gì → mới hiểu, mới accept.
03 · Daily habit
Trust-but-verify
"Understand before approving". 70% problem (Addy Osmani): AI tới 70%, 30% còn lại cần human judgment. Review output mệt hơn review work của con người, không phải dễ hơn.
04 · Avoid atrophy
Skill atrophy mitigation
No-AI sprint định kỳ. SEO lead làm 1 audit thủ công/quý. Junior 6 tháng đầu hạn chế Claude cho fundamentals. Mục đích không phải hiệu suất — giữ "muscle" để biết khi Claude sai.
05 · Quality input
Spec-first thinking
Spec/brief tốt = output tốt 5×. Brief 500-1500 từ với constraint, ví dụ, anti-pattern. Brief < 200 từ — chưa đủ. Side effect: brief tốt → đồng nghiệp con người cũng hiểu nhanh hơn.
06 · Risk awareness
Blast radius mindset
Không bao giờ Claude trực tiếp đụng prod (WordPress, Ads, GA4, GMB). Workflow chuẩn: staging clone → Claude làm → human verify → human apply lên prod. 2s delete = 2 ngày phục hồi.
07 · Override
Critical thinking — biết khi nào override
Claude bịa số liệu SEO rất tự tin: keyword volume, backlink count, citation. Mọi số phải trace về MCP source thực (Ahrefs, GSC, GA4). Plausible-but-wrong là failure mode nguy hiểm nhất ở marketing.
08 · Compounding
Learning loop — đọc Claude output mỗi ngày
Mentor Loop (Martin Fowler): goal nhỏ → Claude plan → check → reflect tradeoff. Đọc Claude diff = reverse mentorship at scale. Khác biệt: actively narrate vs passively bấm enter.
09 · Specifically
Non-dev cần học gì cụ thể
Terminal cơ bản, git cơ bản, JSON/YAML literacy, Markdown, prompt design, plan mode. KHÔNG cần Python/JS/CSS như ngôn ngữ — chỉ cần nhận diện hình dạng đủ để spot khi Claude sai.
10 · Anti-patterns
Không trở thành button-pusher
4 failure mode: over-trust, learned helplessness, prompt-hoarding, Claude-button-pusher. Cure: treat Claude như "OS for knowledge work", không phải "magic answer machine". Build skill, không build prompt library.

Anti-pattern: vòng xoáy thành button-pusher

Mỗi bước "có vẻ vô hại" nhưng cộng dồn → không còn tự suy nghĩ được khi Claude xuống service hoặc sai.

Bước 1
Over-trust
Accept output vì "có vẻ đúng". Không đọc kỹ. Áp lực deadline. Tin Claude hơn tin bản thân.
Bước 2
Learned helplessness
Có vấn đề là copy-paste error vào Claude. Không tự đọc, không tự suy nghĩ. Khả năng debug giảm dần.
Bước 3
Prompt-hoarding
Sưu tập 500 prompt template "khéo". Coi đó là asset. Thực ra là thay thế judgment bằng template.
Bước 4
Button-pusher
Chỉ biết bấm enter. Không hiểu output ra như vậy tại sao. Khi Claude xuống / model đổi → tê liệt.

Lộ trình 4 tuần onboarding marketer non-dev

Từ "tôi không biết terminal là gì" đến "đủ năng lực dùng Claude Code basic". Sau 3 tháng — power user.

Week 1
Terminal cơ bản
cd, ls, cat, grep, pipe. Hiểu file path, ENV var. Cài Claude Code, /help.
Week 2
Git cơ bản
commit, branch, diff, revert. Đọc diff, hiểu staged/unstaged. Push tới GitHub repo.
Week 3
JSON/YAML/Markdown
Đọc & sửa được, biết khi sai cú pháp. Markdown spec/brief. Recognize TS/Python output (không cần viết).
Week 4
Prompt design + plan mode
Viết spec/brief tốt. Plan mode workflow. Slash command. Subagent delegate. CLAUDE.md project-level.

5 câu hỏi tự kiểm tra hàng tuần

Mỗi nhân viên SEONGON dùng Claude Code nên trả lời 5 câu này hàng tuần. Một câu "không" = một rủi ro thực.

  • Tôi có narrate-back được output Claude tuần này không? Nếu không → tôi đang button-push.
  • Tôi có verify ít nhất 1 con số / fact / citation Claude state không? Nếu không → tôi đang đặt cược danh tiếng client.
  • Tôi có làm 1 task without Claude tuần này không? (kể cả task nhỏ) Nếu không → cẩn thận skill atrophy.
  • Tôi có cải thiện 1 spec/brief tuần này không? Spec tốt = output tốt. Brief code-quality nâng dần.
  • Tôi đã review 1 hành động blast-radius lớn trước khi Claude execute chưa? Một câu "không" = một rủi ro thực.
